验收协议第六轮攻击：Q1-R 可证伪合同

“不比 Monaco 差”不再是口号：正确性要求零差异；性能要求每个共同定义的独立成本指标，其 Mona/Monaco 配对比值 95% 置信区间上界不超过 1.00。

Q1-R

同一输入、同一机器、同一合成画面观察器、逐指标 non-inferiority

不使用综合分、平均帧率或内部埋点互相比。外部控制器向两个产品注入相同事件，并用 ScreenCaptureKit 识别首个包含预期像素状态的合成帧；RSS/CPU/energy 对完整进程树聚合。

本轮命中的八个反例

01 · 有限 benchmark 证明所有场景更快有限样本不能推出所有文档、设备和操作上的普遍序关系。发布声明只覆盖固定 baseline、完整 workload manifest 与已证明的复杂度上界。
02 · JS rAF 对比 Metal completion两者不是同一时间点；command buffer completion 也不等于屏幕呈现。共同 oracle 固定为 CGEvent 时间戳到 ScreenCaptureKit 首个目标合成帧。
03 · 只看平均 FPS平均值隐藏尾延迟与掉帧。60 Hz / 120 Hz 分开记录 input-to-present、missed presentation、p50/p95/p99。
04 · Chrome 只量 renderer PIDMonaco 还消耗 browser、GPU、utility 与 worker 进程。Chrome dedicated process tree 全量聚合；Mona sample app 及其 helper/LSP 全量聚合。
05 · GPU memory 使用两套 APIMTLDevice.currentAllocatedSize 与 Chrome MemoryInfra 字段语义不同。跨产品硬门槛使用 OS aggregate physical footprint/IOSurface categories；私有 allocator 数字只做 Mona 泄漏诊断。
06 · 一项更快抵消另一项更慢加权总分会掩盖退化。每个 workload × metric × refresh-rate 都独立判定；任一失败即整节未通过。
07 · 正确性只测正常 UnicodeMonaco model 接受孤立 surrogate，regex/CRLF/grapheme 也有独立规则。raw UTF-16、阈值边界、异常协议、重入与取消全部纳入 differential。
08 · 没有设备就把 gate 推迟当前设备事实已取得，且本期只验 macOS。baseline 固定当前 M4 Pro；iOS/iPadOS 不进入本期通过声明。

采样、可靠性与失败语义

Statistical gate

  • cold：50 fresh-process/profile pairs
  • hot：30 AB/BA alternating pairs；每产品每 pair ≥10,000 frames/actions
  • resource：30 pairs；start/end thermalState 必须 nominal
  • 每 paired-run 先算 cost/p50/p95/p99，再对 ratio 做 10,000 次 bootstrap
  • lower-is-better 的 95% CI 上界 ≤1.00；throughput 先转单位工作成本

Zero / invalid handling

  • Monaco 离散基线为 0：Mona 每个有效样本也必须为 0
  • 样本不足、manifest 不同、thermal 非 nominal：整 pair 作废并重跑
  • CI 跨 1、任一独立 metric 落后、正确性 mismatch：该 section 未通过
  • 不删除 outlier；保留原始 trace
  • refresh、版本或 corpus 改动创建新 baseline revision

Reliability gate

  • 1,000 create/attach/detach/dispose cycles，Mona weak tracker 回到 warm baseline
  • 24h mixed P02–P13 soak；quiescent live allocations 不超过已声明 cache bounds
  • Leaks：0 definite leaks；Main Thread Checker：0；Metal validation：0
  • ASan、TSan、UBSan 分开全套运行：0 finding
  • crash、hang、data loss、half-committed transaction：0

Failure injection

  • allocator denial、memory pressure、Core Text NULL、Metal allocation/present failure
  • LSP malformed/oversize frame、disconnect、restart、late response、duplicate id
  • provider throw/cancel/reenter/late release；host opener/workspace rejection
  • IME reentrancy、folded composition、editor disposal during callback
  • 每次都验证 typed failure、R1 rollback/drop 与 model invariants

Complexity gate

  • Piece Tree edit/search/offset 与 decoration interval operations 保持 Monaco 同阶上界
  • projection/vertical prefix query 不做 document-wide viewport hot-path scan
  • visible rendering 与 viewport rows/changed dependencies 成正比
  • 每项用 operation counters 验证增长曲线，不用 wall-time 代替复杂度
  • 检测到更差阶数即失败，不等待大文件耗时回归

Current status

  • 仓库没有 MonaCode 可执行实现
  • C01–C08、P00–P13、reliability、failure injection 全部未执行
  • 因此当前正确性与性能状态统一为“未通过”
  • screen/controller permissions 尚未授予时，外部 presentation gate 保持未通过
  • 设计闭环不改变任何 empirical status
唯一允许的发布结论
“MonaCode revision X 在 Q1-2026-08-13 baseline、Q1-R corpus 与全部 retained surface 上通过零差异 conformance；在 P00–P13 每个共同成本指标上，配对 Mona/Monaco ratio 的 95% CI 上界均 ≤1.00；核心操作复杂度不高于 Monaco 0.56.0。”
