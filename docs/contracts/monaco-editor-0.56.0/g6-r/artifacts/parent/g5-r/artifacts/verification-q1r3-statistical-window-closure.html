验收协议第八轮攻击：Q1-R3 统计与测量窗口闭包

Q1-R 继续定义 C01–C08 与 P00–P13；Q1-R2 继续定义双基线、total/component 与 collectors。本页覆盖 Q1-R2 的 95% CI、10,000 bootstrap 与短窗口资源采集条款。

Q1-R3

全局不劣结论采用 intersection–union gate；每个 cell 使用确定性、配对、单侧 95% basic-bootstrap 上界

全局 null 是“至少一个预注册 cell 变差”，全局 pass 要求每一个 cell 同时拒绝各自 null。该结构不做 multiplicity 调整；增加 Bonferroni 只降低检验力，不提高此 intersection–union gate 的 size 控制。

本轮六个攻击结果

13 · 多指标必须 Bonferroni这是“任一显著即成功”的 union alternative 规则。当前规则是“全部不劣才成功”。攻击不成立；IUT 的各 component test 直接使用 α=0.05。
14 · 95% CI 已足够明确两侧 95% 与单侧 95% 的上界不同。固定 one-sided upper confidence bound，α=0.05。
15 · 10,000 次 bootstrap 已可复现未指定 estimator、重采样单位、CI 类型与 PRNG。固定 basic paired block bootstrap、1,000,000 resamples、manifest seed。
16 · ratio 对所有成本成立零值、低于分辨率值与负 component delta 让 log ratio 无定义。正值走 log ratio；近零走 difference；负 delta 仍判 invalid。
17 · 单个按键窗口可测功耗本机 powermetrics 默认 5 秒，虽可配置 1 秒，短动作仍不足以形成稳定 interval。延迟逐动作测；资源使用重复 workload 的长窗口并按完成单元归一。
18 · cold startup 可复用 warm 资源窗口复用进程破坏 cold 定义。P00 每 slot 新 profile、新 process tree、ready 后终止；active/empty-host 使用同一 slot schedule。

资源窗口与 cold-start slot

Hot resource window

  • powermetrics 使用 plist、sample-rate=1000 ms
  • 每 window 至少 60 秒、至少 60 个完整有效 interval
  • 同一原子 workload 连续循环；记录完成单元数
  • CPU/GPU/energy integral 除以完成单元数
  • active、own empty-host、neutral idle 时长完全一致

P00 cold resource window

  • 固定 50 个 3 秒 slot，总长 150 秒
  • 每 active slot 创建 fresh profile 与新 process tree
  • ready marker 后立即正常终止；剩余 slot 保持 neutral
  • 对应 own-idle slot 只启动同产品空宿主
  • 任一实例超过 3 秒未 ready：该 block 直接失败

Latency remains direct

  • first/input→present 仍逐事件、逐 frame 观测
  • cold startup latency 使用每个 slot 的 launch→ready
  • 不从 latency 减 idle，不用 1 秒 power sample 代替 latency
  • ScreenCaptureKit frame validity 继续服从 Q1-R2
  • 60 Hz 与 120 Hz 是不同 cell，不混合
覆盖后的唯一发布统计表述：
“在预注册 Q1 cell manifest 上，全局 pass 采用 intersection–union rule：每个 N/M0 与 N/M1 cell 的配对单侧 95% basic-bootstrap upper bound 均不超过 noninferiority boundary；所有 cell 全部通过。”

它只描述固定设备、OS、display、artifact 与 corpus，不外推到未测设备、未测输入或未来版本。
事实索引：Berger 与 Hsu 的 intersection–union 定理给出：若每个 component rejection region 是 level α，只有所有 component null 均被拒绝时才拒绝 union null，则整体 test 仍为 level α，无需 multiplicity adjustment。FDA 的多 endpoint 指南同样列出“每个 endpoint 都成功”的规则不需要 multiplicity adjustment。本机 powermetrics 26.6 手册固定 sample-rate 参数单位为 ms、默认 5000 ms，process energy impact 是 rough proxy，SoC average power 是 estimate 且不得跨设备比较。本页的 1,000,000 basic-bootstrap、60/150 秒窗口与 3 秒 slot 是 MonaCode 冻结的验收协议值，不冒充 Apple 或 Monaco 标准。当前无任何采样结果。
