原生输入对抗结论：I3-R 双平面仲裁

以本机 macOS 26.5 SDK、Apple 2026 Writing Tools 样例和 Monaco Editor 0.56 输入链为事实基线。

I3-R

采用自定义 NSView + NSTextInputClient；系统只投影主选区，EditorCore 保有全部逻辑光标

非组合期仅当 MonaCode 快捷键解析器明确命中命令或 chord 前缀时抢占 NSEvent；其余事件交给 NSTextInputContext。组合期先交给输入法。任何文本写入都只能来自 insertText / setMarkedText，绝不从 event.characters 猜测。

AppKit 单投影NSTextInputClient 的 selectedRange / markedRange 都是单个全文 UTF-16 范围。
NSTextView 不够多个 selectedRanges 除单个范围外必须非零长度，不能表达多个 caret。
Monaco 同构原生 textarea / EditContext 只同步 selections[0]；Cursor compositionType 对每个逻辑 selection 建 command。
真实模型编辑Monaco 每次 composition update 都进入 model edit、version、undo 与 content-change 链。

三条路线的对抗结果

淘汰 I1

AppKit 永远优先

Apple 样例的 handleEvent-first 对普通文本成立；它无法在输入系统之前实现 Monaco 动态 context-key 快捷键、任意 chord 与覆盖式 keybinding。

淘汰 I2

原始按键永远优先

从 keyCode / characters 合成文本会绕过输入法状态机，直接破坏 Option-E dead key、拼音/日文/韩文组合、字符检视器与听写。

采用 I3-R

按状态仲裁的双平面

Keybinding plane 只处理明确命中；Text Input plane 产生全部文本；Editor Input plane 将主投影转换为一次多光标原子事务。

外部编辑、撤销与 marked 样式边界

ModelInputBarrier

  • 任何不携带当前 composition token 的 model/selection mutation，先结束该 model 上全部 editor 的 composition
  • 调用 discardMarkedText，保留已写入文本、清除 editor-local marks；重入 unmarkText 幂等
  • barrier 结束后重新执行 R1 DependencyStamp / ApplyTicket gate
  • 失焦、view dispose、鼠标在 marked 区外落点走同一条路径

Undo / version

  • 每次 composition callback 是一次原子 model transaction，并产生正常 contentVersion 与 LSP didChange
  • 操作类型沿用 Monaco TypingOther；composition start 不强制新 undo stop
  • 是否与前序 typing 合并完全使用 Monaco 的 operation-type 边界
  • unmarkText 只改变 editor state，不伪造 model version

PlainTextMarkedAttributes

  • 广告并渲染：underline style/color、foreground、background、marked clause segment
  • 属性只存在于 editor-local UTF-16 spans，不进入 text model、undo、LSP 或快照
  • 不广告 attachment、glyphInfo、font、text alternatives 与私有 replacement/undoable keys
  • NSString 输入使用 MonaCode 默认 composition underline

几何与错误隔离

  • firstRect 返回首个逻辑 segment 的屏幕矩形；characterIndex 使用 LineLayoutRecord hit-test
  • selection 改变调用 textInputClientDidUpdateSelection；scroll 调用 textInputClientDidScroll；连续 scroll/resize/zoom 由 willStart → invalidateCharacterCoordinates → didEnd 包围
  • 其它 content/coordinate 变化调用 invalidateCharacterCoordinates；handleEvent 已消费的单次变化不重复通知
  • NSRange 使用 checked UTF-16 算术；协议违例不改 model，记录 fault 并结束 conversion
  • 所有入口 MainActor；callback 内无 await，后台不得持有 composition token
