剪贴板与拖放对抗结论：I4-R 三层 Transfer Pipeline

事实基线：Monaco Editor 0.56 源码、本机 macOS 26.6 + MacOSX 26.5 SDK、Apple 2026 custom text engine 样例；iOS 26.5 SDK 只用于验证长期适配边界。

I4-R

核心拥有 DataTransfer 与编辑事务；系统只负责搬运原生 item

公共格式保证跨应用可用，版本化元数据保住 Monaco 多光标/整行语义，同进程注册表承接异步 prepareDocumentPaste。Paste、Drop、Services 最终都进入 R1 PreparedModelCommit / WorkspaceTransaction gate。

Monaco 不是纯文本 paste0.56 保存 line-copy、multicursorText、mode、UUID；Paste Provider 还有 prepare / provide / resolve、yieldTo、additional WorkspaceEdit 与 post-paste selector。
AppKit 有真正的 typed pasteboardNSPasteboard 支持多个 item、custom UTI、changeCount、URL/file URL、HTML；writeObjects 明确返回成功或失败。
延迟供数不能承接 async ProviderNSPasteboardItemDataProvider 的 provideData 回调是同步签名且 nonisolated；不能在回调里等待 async prepareDocumentPaste。
原生多选格式不能当协议本机 NSTextView 实测写入 line-count plist；Apple public 文档只命名 “Multiple text selection”，未公布 payload schema。

三条路线的对抗结果

淘汰 I4-A

AppKit 全托管

只实现 copy/cut/paste + NSDraggingDestination 会丢失多光标分发、整行粘贴、Paste As Provider、yieldTo、WorkspaceEdit 和候选 edit 切换。

淘汰 I4-B

逐行照搬浏览器实现

只用进程内 “最后一次明文→metadata” 映射，是 ClipboardEvent 自定义类型受限的 workaround；在 NSPasteboard 上会无故丢失跨进程/重启后的默认多光标语义。

采用 I4-R

公共格式 + 私有元数据 + 本地 async

MonaDataTransfer 是统一核心；MacPasteboardAdapter 与未来 UIKitItemProviderAdapter 只做类型映射和物化，不参与 Provider 排序或模型编辑。

三层载荷的职责不可混用

1. 公共原生格式

  • 复制成功的最低条件：plain string 写入成功
  • 单选、非纯文本、精确 token snapshot 时附带 HTML
  • 默认阈值对齐 Monaco：少于 65,536 UTF-16 units；显式 Copy with Syntax Highlighting 仅绕过长度阈值
  • URL / file URL 归一为 text/uri-list；不把文件权限伪装成 string
  • 不生成 RTF / RTFD：Monaco rich copy 输出 HTML，纯文本模型也不消费富文本属性

2. CopyMetadataV1

  • binary property list；固定 schema version、transfer UUID、source EOL、language mode、line-copy flag；解码上限 8 MiB
  • 多选保存公共明文中的 UTF-16 segment offsets，不重复保存大段字符串
  • SHA-256 校验无 BOM、little-endian UTF-16 code units；offset 有序、无越界、间隔必须等于 source EOL
  • segment count 不超过 Monaco 对齐的 multiCursorLimit；任何验真失败只退化为普通纯文本 paste
  • native multipleTextSelection 只作为第三方 opaque type 暴露，核心不解析其未公开格式

3. 同进程 Provider 注册表

  • 仅保留当前 copy operation；新 copy、pasteboard owner 变化、model dispose 会取消旧 operation
  • Paste 只等待与候选 provider MIME 匹配的 prepare 操作
  • 高优先级 copy provider 覆盖同类型的低优先级结果，与 Monaco 一致
  • UUID 还必须匹配当前注册表和内容摘要；外部伪造 UUID 不能取得进程内数据
  • App 退出后只失去 provider 私有数据；公共文本、HTML 与默认多光标 metadata 仍可用

六类用户操作的精确语义

操作
I4-R 行为
可观察效果 / 边界
Copy / Cut
selection 按起点排序；空 caret 选项开启时复制唯一整行并附 model EOL。Cut 仅在 public plain write 成功后执行一次多选删除事务，前后各一 undo stop。
metadata/HTML 写失败只降级，不造成已删文本无剪贴板；一次空 caret 才带 line-copy 标记，多空 caret 依靠 segment 分发。
默认 Paste
segment 数等于 cursor 数则 1:1；否则 spread 模式在线数等于 cursor 数时逐行；再否则全文复制到每个 selection。line-copy 只在空 selection 处按整行插入。
对齐 Monaco PasteOperation；使用正常 paste undo 边界和 CursorChangeReason.Paste。
Paste / Paste As Provider
按 advertised MIME 和 kind 过滤，稳定拓扑排序 yieldTo；自动 Paste 初选默认/配置 edit，Paste As 先选 edit；resolve 后把 snippet 应用到每个 target，再合并 additional WorkspaceEdit。
自动 handler 可取消并退回 basic paste，但只在原 modelVersion + selections 仍有效时；Paste As 取消或无 edit 时不修改模型。
同 editor 内部 Drag
只拖鼠标命中的唯一 selection；column selection 禁用；Option 表示 copy。move 为删除源+插入目标的一次 commit，drop 在 selection 内为 no-op，copy 仅允许落在两端。
严格对齐 Monaco：执行后 secondary cursors 被清除；同 view 以外一律视为外部 copy，不做跨 editor/cross-model move。
外部 Drop
drop 先设置单个目标位置，再运行 DocumentDropEditProvider；ticket 锁定 model value，不锁定后续 cursor movement。默认 provider 含 plain text、absolute URI/path、workspace-relative path。
URI list 存在时默认 plain provider 让位；Drop 不提供 HTML 默认 edit。源文档绝不因外部 drop 被删除。
macOS Services / Writing Tools
NSView 实现 NSServicesMenuRequestor，只广告 plain string；send/return 只作用 primary selection。返回文本走 ServiceReplace commit，不进入 Paste As Provider。
多 selection 无可验证的一一映射，所以 secondary 不改。只读 editor 可 send、不可 return；收到 return 前执行 model-wide input barrier。

状态有效性、撤销与系统边界

Paste / Drop tickets

  • 自动 Paste 与 Paste As：model identity + contentVersion + 完整 selections + provider registry epoch
  • Drop：model identity + contentVersion + captured drop position；光标移动不取消
  • default paste 无异步候选时同步落盘；有候选时显示可取消进度
  • Provider 只收到 immutable model snapshot 和 immutable TransferSnapshot

Post-edit selector

  • 只有多个 edit 且配置允许时显示；cursor move 或任何 touched model 变化即关闭
  • 每次 apply 记录 WorkspaceUndoGroupID 和所有受影响 model 版本
  • 切换候选前验证该 group 仍是所有模型栈顶，再整体 undo、resolve、apply 新候选
  • 任一模型被其它操作修改后，禁止用一次普通 undo 猜测回滚范围

IME 与 responder

  • 当前 view 有 marked text 时 Copy 不可用，严格对齐 AppKit 已公开行为；I4-R 同时禁用 Cut，避免删除未提交 composition
  • Paste、Drop、Services return、drag start 属于外部/非 token mutation，先走 I3-R ModelInputBarrier
  • 所有 NSResponder / NSDragging / NSServices 回调在 MainActor；回调中不 await
  • 菜单校验不读取 general pasteboard 内容；只在明确用户 paste/drop 时物化

明确不扩张的范围

  • 不生成 RTF/RTFD，不实现富文本模型或 attachment paste
  • 不实现跨 editor / 跨 model drag-move；外部 drop 始终 copy
  • 不持久化 provider 私有 copy 数据，不把 async Provider 塞进同步 pasteboard callback
  • 不依赖 Apple 未公开的 multipleTextSelection payload schema
  • iOS/iPadOS 复用核心，后续仅增加 UIPasteboard / NSItemProvider / UITextDrop adapter
