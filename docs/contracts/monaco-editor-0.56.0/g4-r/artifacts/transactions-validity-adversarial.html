跨模型事件的确定反例

上一版若逐个 fire，无法保证观察顺序
commit A-v2 + B-v2›fire A-v2›A listener edits B›observer sees B-v3›observer sees B-v2

修正后的唯一合法顺序：enqueue[A-v2, B-v2] → drain A-v2 → drain B-v2 → drain reentrant B-v3。这个要求必须写入 GlobalModelEventHub，而不是依赖 MainActor 的串行性。

修正版：DependencyStamp + 逐功能 ReconciliationContract

L2-R 的 30 个语言表面逐项登记，不能靠默认猜测

Exact editor state

navigation、rename resolve、outline cache 等：model instance、contentVersion、position/selection 依赖不变。

Edit-log replay

semantic tokens：记录请求期间 content changes，按 Monaco 算法映射 token ranges，然后立即调度刷新。

Continuation state machine

completion / inline completion：同一触发会话内延续过滤或重取；展示和应用分成两个 ticket。

Bounded-change predicate

on-type format、completion additional edits：检查期间 edits 是否越过功能定义的安全边界。

Server-authoritative push

无版本 diagnostics：最新 publish 覆盖；作为 URI marker stream 展示，不标记“版本已验证”。

Workspace/session scoped

workspace symbols 等不绑定当前 model，但必须匹配 provider registration、configuration 与 LSP session epoch。

R1 必须写入设计的恢复边界

LSP 生命周期按所有权拆分

  • Owned process / recreatable factory：滚动 180 秒内第 5 次 crash 打开 circuit breaker
  • Remote transport：只声明 reconnect；客户端不声明“重启远端 server”
  • Embedded：只有 host factory 能重建实例；fatal process crash 不存在进程内恢复
  • session dispose/restart 清理该 session 的 diagnostics、dynamic registrations 与 pending requests

Diagnostics 与 geometry result

  • 有 version 且 model open：只接纳精确 contentVersion
  • 无 version：最新 server push，markers 随 Monaco 式 decoration stickiness 移动
  • didClose 不清 markers；empty publish、owner/session dispose 才清
  • LineLayoutRecord 必须通过 V1-R4 全量 DependencyStamp；CT failure 与 renderer generation failure 分开统计
