原生输入第四轮攻击：I3-R2 keybinding 与 IME 排序闭包

I3-R 的 NSTextInputClient 双平面与 R1 commit 路径保持有效。本页覆盖 F1-R 的 379 macOS keybindings 在 AppKit 上的 event normalization、resolver、chord 与 text-input routing。

I3-R2

每个 keyDown 先形成 immutable MonaKeyEvent 并解析 keybinding；只有未消费事件才进入 interpretKeyEvents

Command 映射 Monaco meta/CtrlCmd，Control 映射 ctrl/WinCtrl，Option 映射 alt，Shift 映射 shift。keybinding command 与 NSTextInputClient edit 永远不会消费同一 keyDown。

本轮四个命中

23 · NSEvent.keyCode 直接等于 Monaco KeyCode两套 enum 数值与布局语义不同。specialKey、characters(byApplyingModifiers: [])、numericPad 与固定 mapping table 生成 Monaco semantic key。
24 · 先 interpret，再看 command同一 keyDown 会同时写字和执行命令。resolver 先判定；消费后不调用 interpretKeyEvents。
25 · chord timeout 就是精确 5 秒0.56.0 每 500 ms 检查一次，条件是 elapsed>5000 ms。复制 polling 与严格大于条件；focus loss 立即退出。
26 · Option/dead key 没有 basic keyApple 明确 charactersIgnoringModifiers 对 Option-e 返回 e，并推荐用于 hardware-independent keyboard equivalents。resolver 使用无 modifier translation；text insertion 仍由输入系统处理。

Resolver 与 chord 状态机

Resolver parity

  • 379 defaults 保留 primary/secondary/mac override
  • defaults 按 weight1、command 字典序、weight2 升序；resolver 从冲突数组尾部取首个 when match
  • dynamic rules weight1=1000、weight2=0，并在 defaults 后进入 override 集
  • command removal rule、when parser 与 context snapshot 保留
  • matched non-bubble command 消费 event；args/failure notification 保留

Multi-chord

  • MoreChordsNeeded 消费首键并进入 prefix state
  • 每 500 ms 检查 focus 与 elapsed
  • elapsed 严格大于 5000 ms 才退出
  • 无匹配后续键也消费、提示、退出
  • chord mode 不调用 interpretKeyEvents，不强制提交或取消既有 marked text

Single modifier

  • 监听 flagsChanged/key-up 语义快照
  • 同 modifier 第二次 release 在 300 ms 内触发
  • 中间出现其它 modifier/key 立即清空 candidate
  • 不同 modifier 第二次 release 不触发
  • timer 使用 ContinuousClock，不读取 wall clock

IME routing

  • matched command/chord：不调用 interpretKeyEvents
  • unmatched：只调用一次 interpretKeyEvents([event])
  • 所有 insert/setMarked/unmark/selector callback 进入 I3-R transaction
  • composition event 时序由 callback state 生成
  • 不从 event.characters 直接写 model

Acceptance

  • 同一 CGEvent trace 注入 Chrome M0 与 MonaCode
  • 比较 resolved command ID、args、when snapshot、consume bit
  • 比较 chord state/status/timer boundary
  • 比较最终 model/selection/marked range
  • 当前输入源 manifest 固定 com.apple.keylayout.ABC

事实索引：固定 Monaco core 的 StandaloneKeybindingService 把 DOM keydown 先交 AbstractKeybindingService，未被 command 消费时浏览器才继续默认输入；它使用 StandardKeyboardEvent 与 USLayoutResolvedKeybinding。KeybindingsRegistry sorter 按 weight1、command lexicographic、weight2 升序排列 defaults，KeybindingResolver 从候选尾部选首个 when match；dynamic overrides 位于 defaults 之后。AbstractKeybindingService 每 500 ms 检查 chord，elapsed>5000 ms 或 document focus loss 时退出；single modifier candidate 300 ms 清除。Apple NSEvent 文档说明 charactersIgnoringModifiers 忽略 Shift 以外的 modifier，Option-e 返回 e，并用于 hardware-independent keyboard equivalents；characters(byApplyingModifiers:) 用指定 flags 完全替换现有 flags；keyCode 是 hardware-independent virtual code，specialKey 表示功能键。本机 current layout probe 返回 com.apple.keylayout.ABC。当前无实现结果。
