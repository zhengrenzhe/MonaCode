宿主边界修正：H1-R2 opener 与计数闭包

本页不增加功能，只消除 H1-R 的“七组”与八个 JSON 条目之间的歧义，并用 Monaco 0.56.0 public declaration、实现和 H2-R registry 事实收敛 opener。

H1-R2

唯一口径：7 组、10 个具体类型；不存在第三个 MonaResourceOpener

H1-R 自身新定义 8 个类型；opener 组复用 F1-R4 已保留的 MonaLinkOpener 与 MonaCodeEditorOpener，因此全组共有 10 个具体类型。F1-R 的 MonaResourceOpener 只是旧统称。默认外部打开继续 unhandled，不引入 NSWorkspace、URL、文件系统、网络或新的宿主回调。

机器计数

7contract groupsEnvironment、Opener、Workspace、Command、Log、LSP transport、MultiDiff。
8H1-R defined types原 H1 manifest 的 hostContracts 数组长度，事实不变。
2F1 opener interfacesILinkOpener 与 ICodeEditorOpener 均 retained-native-mapping。
10concrete types8 + 2；register 函数另有 2 个，不混入类型计数。

opener 的可观察闭包

调用与完成

  • MainActor 按 registry 顺序调用
  • boolean-or-thenable 走 F1-R5 MonaThenable 适配
  • 结果在当前 callback stack 后由 MonaMicrotaskQueue 消费
  • rejection 是操作失败，不回退旧 opener

输入与所有权

  • link 接已解析 MonaURI
  • code editor 接 live source editor
  • target 明确 absent / position / range
  • 不复制 editor 或 model state

明确不存在

  • 无第三个 MonaResourceOpener symbol
  • 无隐式 NSWorkspace.open
  • 无 URL / 文件 / 网络 fallback
  • 无 per-editor opener registry
