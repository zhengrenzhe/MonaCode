布局与渲染对抗结论：V1-R 精确 View Graph

事实基线：本地锁定的 Monaco Editor Core 0.56 源码、MacOSX 26.5 SDK 公共头文件、Apple TextKit 2 / Core Text / Metal 官方资料；性能结论仍只由当前 M4 Pro 的既定差分基准产生。

V1-R

MonaViewGraph 是唯一已接受坐标真相；TextKit 2 / Core Text + Metal 只能生成带票据的布局提案

全量 projection、折叠、注入文本、view-line 数、行高、view zones 与纵向前缀和必须精确；只有视口 glyph/run、绘制 surface 和 paint cache 可以惰性。每个 LayoutGeneration 只激活一套主文本 Backend Bundle，整代原子切换，不逐行混用两套排版几何。

Monaco 全量计算换行ViewModelLines 构建时把每个 model line 送入 line-break computer，再把各行 view-line count 放入 ConstantTimePrefixSumComputer。
Monaco 纵坐标精确LinesLayout 用 view-line 高度和独立 whitespace/view-zone 序列计算前缀和、scrollHeight、line↔Y 与 viewport。
TextKit 2 离屏是估算系统始终使用 noncontiguous viewport layout；离屏尺寸在 ensureLayout 前可以不准确，Apple 明确说明全量 ensure 代价高。
TextKit 2 可做自定义后端SDK 允许 custom content manager/location/element/fragment、viewport surface 和 layoutQueue；因此可接 Piece Tree snapshot，而非复制一份可编辑全文。
Metal 不负责文字排版Metal 只处理 buffer/texture/shader/drawable；Core Text 才执行字符到 glyph、字形顺序、kerning、line break、hit test 与 font fallback。

三条路线的对抗结果

淘汰 V1-A

TextKit 2 独占文档布局

把 usageBounds、viewportRange 和 fragment estimates 直接当编辑器真相，无法保持 Monaco 的精确离屏 line↔Y、稳定 scrollHeight 和全量 view-line prefix sum。强制全量 ensureLayout 又必须单独通过性能门槛。

淘汰 V1-B

立即全量自研 Metal 编辑器

Metal 没有 typesetter。此路线仍需 Core Text，并一次性接管 Unicode shaping、bidi、color glyph、hit testing、IME geometry、VoiceOver geometry 与资源恢复；当前没有基准证明这项扩张必要。

采用 V1-R

精确核心 + 整代 Backend Bundle

核心先固定 Monaco 等价的坐标与布局协议；TextKit 2 是首个候选 bundle，失败后沿既定阶梯切换。后端变化不修改 Model、Input、Commands、Providers、Widgets 或 public geometry API。

Exact 与 Lazy 的边界

提交 LayoutGeneration 前必须完整、精确

  • 每个 model line 的 visible/hidden 状态、injected-text UTF-16 mapping、wrap break offsets 与 view-line count
  • model position ↔ view position、wrapped-line affinity、faux indent 与 injected-text cursor stops
  • 默认/自定义 view-line height；top/bottom padding；view zone 的 after-line、ordinal、height、minWidth
  • view-line count prefix sum、line↔absolute Y、scrollHeight、visible row interval、sticky-scroll source rows
  • API 驱动的 layout mutation 在 graph 提交并发出事件前不得暴露半更新状态；任何 TextKit estimated bounds 不进入上述索引

只在 viewport + overscan 物化

  • glyph runs / NSTextLineFragment、ink bounds、texture atlas entry、line tile 与 draw command
  • 精确横向 caret stops、selection segments、bidi visual segments 与 content width measurement
  • semantic token 色彩、paint-only decoration、selection/caret animation 与 hover state
  • minimap tiles、overview ruler pixels、sticky-scroll surface 与 widget view reuse
  • 交互目标行缺 record 时同步执行 InteractionGeometryBarrier；不返回估算 hit-test 或 IME candidate rect

关键攻击与 V1-R 防线

攻击 1 · TextKit estimate 污染 scrollHeight

防线：estimate 只留在 backend 私有预取；ProjectionIndex、HeightIndex 和 public geometry 只安装 exact batch。

攻击 2 · TextKit 与 Metal 逐行 fallback

防线：Apple 没有保证 NSTextLineFragment 与独立 CTLine 几何逐位相同；主文本禁止逐行跨 bundle，切换以完整 generation 为单位。

攻击 3 · 异步布局晚到覆盖新文本

防线：LayoutStamp 精确包含 model identity/version、projection/metric/style epoch、container width、backing scale、backend id/generation；任一不等即丢弃。

攻击 4 · 快速滚动出现错误 hit-test

防线：FrameSnapshot 只提交同代完整可见 records；鼠标、IME、VoiceOver 请求缺失行时先过 InteractionGeometryBarrier。

攻击 5 · 把 view zone 做成 attachment

防线：Monaco 本身把 zone 当 whitespace；V1-R 也把它放在独立纵向索引，文本 offset、selection 与 LSP range 均不变。

攻击 6 · Metal 自己处理 RTL/emoji

防线：Core Text 固定为 T3 的 shaping/bidi/font-fallback 权威；Metal 只合成 Core Text 产出的 glyph/run 纹理和几何，不实现 Unicode 排版。

攻击 7 · 主题变化触发全量 reflow

防线：font/spacing/injected content 进入 metric/projection epoch；颜色、下划线、selection/caret 只进 paint epoch。两类 invalidation 不互相升级。

攻击 8 · 高刷只看平均帧耗时

防线：沿用已锁定的 60/120 Hz、p50/p95/p99、cold/hot 与资源指标；Metal 使用 CAMetalDisplayLink 的 target timestamps，任何独立指标落后即失败。

事实证据：Monaco 0.56 的 viewModelLines / modelLineProjection / monospaceLineBreaksComputer / domLineBreaksComputer / ViewLayout / LinesLayout / LineHeights / ViewLines / ViewLinesGpu / ViewGpuContext；其中 GPU 选项默认 off，GPU line path 明确拒绝 RTL 与超过 2,000 columns 的行并交给 DOM path。MacOSX26.5.sdk 的 NSTextContentManager、NSTextLayoutManager、NSTextViewportLayoutController、NSTextLayoutFragment、NSTextLineFragment、CTTypesetter、CTLine、CTRun、CAMetalDisplayLink 与 NSScreen headers。Apple “Meet TextKit 2” 明确说明 TextKit 2 始终 noncontiguous，离屏信息未 ensureLayout 时不保证准确且全量 ensure 代价高。当前仓库仍无 MonaCode 可执行切片，所以没有任何后端取得性能通过结论。

采纳 V1-R

锁定唯一 View Graph、exact/lazy 边界、三档 Backend Bundle 与整代原子切换。
