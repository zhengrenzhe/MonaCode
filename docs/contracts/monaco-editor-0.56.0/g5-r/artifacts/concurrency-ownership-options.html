并发所有权：live model 放在哪里？

三种方案都允许后台 LSP、Diff 和布局；区别是 live model 的修改入口，以及同步事件能否保持 Monaco 语义。

已锁定前提：ITextModel 等价 API 是同步 API；输入事务在返回前完成版本递增与事件投递；后台代码只能读取 immutable versioned snapshot。
推荐 A

A · MainActor live model

Model 不依赖 AppKit，但 live state 与 EditorCore 统一归属 MainActor。
  • UI 输入热路径没有锁、没有 executor hop。
  • 同步 API 与同步事件保持 Monaco 顺序。
  • 后台拿 Sendable snapshot；结果回 MainActor 过版本闸门。
  • 后台发起修改必须切回 MainActor。

B · 内部锁保护

任意线程都能同步读写同一个 live model。
  • 每次输入都进入锁。
  • 必须额外实现跨线程事件排序、重入和等待。
  • 监听器可再次编辑时存在锁与投递队列耦合。
  • 调用方自由度最高，核心复杂度最高。

C · 独立 Model Actor

所有 live model 操作经 Swift actor 串行化。
  • 数据竞争由 actor 隔离。
  • 编辑与读取 API 变为 await。
  • 输入路径增加 actor hop。
  • 不再等价于 Monaco 的同步 ITextModel API。
