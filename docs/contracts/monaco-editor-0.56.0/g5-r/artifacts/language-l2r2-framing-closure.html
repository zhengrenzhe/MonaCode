LSP 传输收敛：L2-R2 帧与生命周期合同

L2-R 的 30/25/5 provider 架构保持不变；本页补齐字节帧、JSON-RPC、transport ownership 与纯文本身份。发生冲突时以 L2-R2 为准。

L2-R2

协议解析只读 bytes；model positions 只用 raw UTF-16；进程启动不是 LSP 前提

FrameCodec、RawUTF16JSONCodec、JSONRPCSession、MonaMessageTransport 四层分离。macOS 宿主可注入 stdio process；in-memory、socket 或远端 transport 使用同一 byte contract；长期 iOS/iPadOS 不依赖 Process。

命中的六个协议反例

01 · 按换行读取 JSONJSON body 可含空白和转义换行。只按 ASCII header 中唯一 Content-Length 的 byte count 切 body。
02 · Foundation JSON String 是透明容器`\uD800` 属于合法 JSON escape，但 Swift String 不保存孤立 UTF-16 unit。string token 使用 raw UInt16 parser/encoder。
03 · JSON-RPC batch 属于兼容增强LSP 3.18 明确不支持 batch。顶层 array 直接返回 InvalidRequest 并关闭该 session。
04 · response 按发送顺序匹配LSP 允许无依赖请求乱序返回。pending map 的 key 是 integer|string id；epoch 隔离重启前响应。
05 · LSP 等于本地子进程协议只定义消息，不定义 binary discovery。process provider 是 macOS host adapter；核心只依赖 MonaMessageTransport。
06 · plaintext 是首发语言包纯文本无需 provider、tokenizer 或 profile。`plaintext` 仅是保留 languageId/fallback metadata，不计入 0 个生产语言内容。

生命周期与本期内容边界

Session identity

  • initialize 成功后进入 running；shutdown 后只接受 exit
  • 请求 id 保留 integer/string 类型，不做字符串归一化
  • 同方向未完成 id 重复：protocol error + close
  • 乱序 response 通过 id 归并；未知/旧 epoch response 丢弃并记录
  • 未知 request 返回 MethodNotFound；未知 notification 记录后忽略；cancel 后仍消费最终 response

Document identity

  • 一个 URI/model/session 只发一次 didOpen
  • 同步模式服从 server capability：none/full/incremental
  • positionEncoding 只广告 UTF-16
  • workspace/applyEdit 进入宿主授权的 R1 multi-model transaction
  • restart 创建新 epoch，并重建 open-document state

Shipped content

  • 30 registry surfaces、25 LSP mappings、5 direct-only API 全部存在
  • 确定性 direct fixture 30 面；in-memory LSP fixture 25 面
  • 生产 language definition/profile/provider/server 数均为 0
  • `plaintext` 是核心 fallback metadata，不注册 provider
  • 组件不发现、下载、更新或签名 LSP binary
事实索引：LSP 3.18 规范固定 gh-pages commit `8b9fab8f0912b694c795d05c1d5e9d357bee0193`，`specification.md` SHA-256 `67e09b5458884dad63631a4cc7f4ea72b659b023e950eb0f7fa7311355cde3d7`。Base Protocol 指定 ASCII header、CRLF、必需 Content-Length byte count、UTF-8 content；request id 是 integer|string；response 可乱序；协议明确不支持 JSON-RPC batch。Monaco model 与 LSP positions 均以 UTF-16 code units 对齐。8 KiB/64 MiB/256 MiB、nesting 128 与 pending 4096 是 MonaCode 已冻结的防御上限，不冒充 LSP 标准值。
