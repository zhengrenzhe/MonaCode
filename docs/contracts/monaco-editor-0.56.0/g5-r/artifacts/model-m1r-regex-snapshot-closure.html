文本模型第三轮攻击：M1-R 可执行合同

目标仍是 MonaCodeModel 对 Monaco Editor 0.56.0 的 ITextModel 可观察语义等价；Swift 动态类型差异、DOM、JS 对象身份不属于等价域。

M1-R

Persistent raw-UTF16 Piece Tree + Monaco event/undo semantics + ECMAScript search runtime

MainActor 只交换 current root、版本、undo/decoration state；后台 snapshot 持有不可变 root。所有文本、搜索、捕获组、offset 和事件 payload 都以 UTF-16 code units 表达，Swift String 只作为“已验证为合法 Unicode”的便捷入口。

本轮命中的九个反例

01 · NSRegularExpression 等价Monaco find 使用 JavaScript RegExp，固定 flags 为 global + unicode，按选项增加 ignoreCase/multiline。ICU 语义被禁止作为真相；实现 raw-UTF16 ECMAScript regex。
02 · Snapshot 直接共享 mutable RB tree后台遍历期间 live edit 会修改 node、父指针与 metadata。Piece nodes/buffers 发布后不可变；edit path-copy，snapshot O(1) retain root。
03 · Swift String 可保留 model 全域Swift String 无法表达孤立 surrogate；Monaco 可以。MonaText/MonaTextSlice 保存 UInt16；禁止经 String 做 canonical round-trip。
04 · 最新 UAX29 等于 Monaco0.56 自带 GraphemeIterator 和生成表，并简化 GB11/GB12 状态。光标、删除、visible-column 逐句移植该版本，不替换为系统 tokenizer。
05 · 一事务固定 version +1EOL、setValue、undo/redo 有各自增量与 alternativeVersion 恢复规则。逐分支差分；不抽象成统一“事务号”。
06 · Undo 可直接保存所有 old rootsroot retention 会让删除的大文本长期存活，改变 Monaco 资源行为。undo 保存 inverse edit elements；root 只由短生命周期 snapshot/transaction retain。
07 · LSP JSON 可经 Codable Stringescaped isolated surrogate 经 Swift String 会修复或拒绝。JSON-RPC string value 使用 raw UTF-16 parser/encoder；Content-Length 仍按 UTF-8 bytes。
08 · 全词边界交给 regex \bITextModel 另用 wordSeparators classifier 检查 match 两侧；零长度 match 还有 surrogate-aware 前进规则。完整移植 Searcher/isValidMatch，不改成 ICU word boundary。
09 · surrogate pair 中间对所有 API 都非法`validatePosition` 会前移，但 `getOffsetAt` 使用 relaxed validation，`getPositionAt` 与 decoration range 能观察 pair 中间列。严格/relaxed/range-expansion 三条路径逐 API 移植。

模型边界与资源政策

Monaco thresholds 原值

  • large-file size：20 MiB
  • large-file line count：300,000
  • heap operation：256 Mi UTF-16 units
  • multi-cursor 默认 10,000、合法上限 100,000
  • 阈值只触发同等功能策略，不删 model text

Swift public surface

  • MonaText 是 canonical raw-unit value
  • live mutable MonaCodeModel API 标注 `@MainActor`，在 MainActor 内保持同步返回/同步事件；后台只读使用 Sendable immutable snapshot
  • Swift String overload 只负责合法 Unicode convenience
  • JS NaN/Infinity/coercion 与跨 actor 同步调用不属于 Swift typed API 等价域
  • Position/Range validation 逐 API 移植；一个 URI 只允许一个 live registered model

ECMAScript runtime

  • 不嵌入 JavaScriptCore/QuickJS/V8
  • 不使用 NSRegularExpression 充当兼容层
  • parser、compiler、executor 直接消费 UInt16
  • compiled pattern cache key 含 source + 实际 g/u/i/m flags
  • 同步 ITextModel.find* 不设自定义 timeout/step cutoff；异步 Find UI 只可丢弃尚未发布的 snapshot result

设计状态与实证状态严格分离

设计已封闭

  • canonical encoding、snapshot ownership、Piece Tree publication
  • regex、word、grapheme oracle
  • undo/event/version transaction boundary
  • typed Swift API 的等价域与 DOM/CSS 排除项

当前未通过

  • 仓库没有 MonaCodeModel 实现
  • ECMAScript regex、persistent Piece Tree、event differential 均无产品结果
  • 所以当前不能宣称 ITextModel 已等价或性能不低于 Monaco
  • 实现后任一 differential mismatch 即 M1-R 未验收
事实索引：Monaco Editor v0.56.0 tag 13f0c872，core dependency 0.56.0-dev-20260625；`pieceTreeBase` 的 AverageBufferSize=65535；`textModel` 的 20 MiB / 300K lines / 256M units thresholds；`validatePosition` 使用 SurrogatePairs validation，`getOffsetAt` 使用 Relaxed validation，`getPositionAt` 直接按 raw offset 返回，`validateRange` 对 pair 内 endpoint 执行前移/外扩，decoration tracked ranges 使用 relaxed validation；`textModelSearch` 固定 global+unicode、按 matchCase/multiline 条件增加 ignoreCase/multiline，默认 limit 999，并使用 LF multiline view、CRLF compensation、wordSeparators 与 zero-length surrogate recovery；`strings.GraphemeIterator` 的生成表与 GB11/GB12 简化。本机固定浏览器：Chrome 151.0.7922.109，V8 15.1.206.16。
