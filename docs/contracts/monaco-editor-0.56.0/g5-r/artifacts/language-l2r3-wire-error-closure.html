语言基础设施第五轮攻击：L2-R3 wire encoding 与错误方向闭包

L2-R 与 L2-R2 的 30 surfaces、25 LSP mappings、transport/session/limits 保持有效。本页覆盖 L2-R2 的 response id、Content-Type alias、outbound JSON 与统一 error response 条款。

L2-R3

固定的是 LSP 3.18 开发中规范的一个 commit snapshot，不是浮动的“3.18 最新版”

所有 wire fixture 绑定 gh-pages commit 8b9fab8f 与 specification SHA-256 67e09b54。未来 3.18 修改、3.19 或 server-specific extension 都创建新 protocol baseline；本期不会静默吸收。

本轮四个命中

19 · 所有 message id 只允许 integer|stringRequestMessage 是 integer|string；ResponseMessage 明确再允许 null。null 只接收在 error response，用于无法关联 request 的 peer error。
20 · utf8 是规范别名固定 3.18 snapshot 写明当前唯一 encoding 是 utf-8。删除无依据的 utf8 alias；field value 大小写不敏感但 token 必须是 utf-8。
21 · decoder 完整等于 codec未定义 encoder 会让 isolated surrogate、Content-Length 与 fixture bytes 漂移。冻结 raw-UTF16 deterministic JSON encoder。
22 · 所有 malformed input 都回 error坏 header 无可靠 frame；坏 response 也不能再回 response。按 frame/request/response 方向分别处理。

Role-sensitive error policy

Frame failure

  • invalid ASCII/header/length/limit 不读 body
  • 不发送 JSON-RPC response
  • 关闭 transport write/read halves
  • fail 全部 pending request
  • 记录 typed frame reason，不记录敏感 body

Body/request failure

  • 合法 frame 内 JSON parse error：写 ParseError id=null 后 close
  • 合法 JSON 的 invalid request：写 InvalidRequest
  • 可解析 request id 时原样返回；否则 id=null
  • 写 half 已失败时只 close
  • 未知合法 request：MethodNotFound，不 close

Response failure

  • invalid response 不再发送 response
  • non-null unknown id、duplicate response、result+error 均 close
  • null error response fail 全部 pending 后 close
  • old session epoch bytes 由旧 transport owner 消费并丢弃
  • cancelled request 的最终合法 response 仍消费后释放

Content-Type 与 JSON decoder 覆盖

Content-Type

  • header 可完全缺省
  • media type 大小写不敏感
  • 唯一 charset token 是 utf-8
  • utf8、utf-16、其它 media type 全部拒绝
  • unknown/duplicate parameter 拒绝

Inbound raw values

  • UTF-8 scalar 解码成一个或两个 UInt16
  • escaped isolated surrogate 原样保存
  • escaped valid pair 保存两个 units
  • duplicate object key 采用最后值，与固定 JS oracle 一致
  • LSP typed integer 再执行 32-bit range validation

Current status

  • 规范与 encoder/decoder/error table 已冻结
  • 仓库没有 codec 或 transport implementation
  • 没有 golden byte/malformed/session fixtures
  • LSP C06 当前未通过
  • 生产 language/provider/server 内容仍为 0
事实索引：固定 3.18 specification 首段明确写明该版本仍 under development。Base Protocol 固定 ASCII header、CRLF、Content-Length byte count、UTF-8 为当前唯一 encoding、禁止 JSON-RPC batch。RequestMessage id 是 integer|string；ResponseMessage id 是 integer|string|null；success 必须有 result 且无 error，failure 必须有 error 且无 result。协议 integer 范围是 −2³¹…2³¹−1。L2-R3 的 deterministic byte representation、严格 Content-Type、close policy 与 limits 是 MonaCode frozen protocol profile；服务器需要其它 profile 时必须创建显式新 baseline。当前没有实现结果。
